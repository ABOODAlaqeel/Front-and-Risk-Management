# نظام إدارة المخاطر واستمرارية الأعمال — الواجهة الأمامية

> واجهة ويب مؤسسية لإدارة المخاطر، ومتابعة خطط المعالجة، وتحليل المؤشرات، ودعم استمرارية الأعمال والتعافي من الكوارث ضمن تجربة محمية بالصلاحيات.

[معاينة النسخة المنشورة](https://front-and-risk-management.vercel.app)

## نظرة عامة

يوفّر المشروع تطبيق SPA مبنيًا بـ React وTypeScript لإدارة دورة حياة المخاطر من التسجيل والتقييم إلى التحليل والمعالجة والتقارير. يدمج التطبيق بين واجهات مؤشرات ولوحات بيانات ورسوم بيانية، وتدفقات مصادقة، ومسارات محمية بحسب الصلاحيات. ويمكن تشغيله في وضع تجريبي يعتمد على التخزين المحلي أو ربطه بخدمة API خارجية عبر متغيرات البيئة.

| المحور | التفاصيل |
| --- | --- |
| **نوع المشروع** | واجهة نظام إدارة مخاطر مؤسسية |
| **الإطار** | React 18 وVite 7 وTypeScript |
| **التنسيق والمكوّنات** | Tailwind CSS ومكوّنات Radix UI |
| **الحالة والبيانات** | TanStack Query وAxios وReact Hook Form وZod |
| **الرسوم والواجهة** | Recharts وLucide React وSonner |
| **المصادقة** | جلسات وتوجيه محمي وفحص صلاحيات على مستوى المسار |

## الوحدات الوظيفية

يتوزع التطبيق على وحدات مترابطة تخدم فرق المخاطر والإدارة والامتثال. تخضع معظم الوحدات لمسارات محمية للتحكم في من يستطيع العرض أو الإنشاء أو التعديل أو الإدارة.

| الوحدة | أمثلة على القدرات المتاحة |
| --- | --- |
| **لوحة القيادة** | ملخصات المخاطر، مؤشرات الأداء الرئيسية، مؤشرات المخاطر الرئيسية، الرسوم والتنبيهات. |
| **سجل المخاطر** | عرض المخاطر وإضافتها وتعديلها وتتبعها، مع صفحة متابعة مخصصة. |
| **التحليل والتقييم** | لوحة تحليل ومصفوفة مخاطر ونماذج تقييم. |
| **المعالجة والسياسات** | خطط معالجة المخاطر وإدارة وثائق السياسات والإجراءات. |
| **استمرارية الأعمال** | خطط BCP وخطط التعافي من الكوارث والخدمات والاختبارات ذات الصلة. |
| **التقارير والحوكمة** | تقارير تنفيذية وقياسية ومخصصة، وحوكمة اللجان، وسجل تدقيق. |
| **الإدارة** | المستخدمون والأدوار والصلاحيات وإعدادات النظام والنسخ الاحتياطي. |

## المتطلبات

يتطلب المشروع Node.js حديثًا مع npm. استخدم `npm ci` بدلًا من `npm install` عند أول إعداد للمشروع لضمان تثبيت الاعتماديات وفق `package-lock.json`.

## الإعداد والتشغيل

انسخ نموذج البيئة أولًا، ثم اختر الوضع التجريبي أو وضع الربط بخدمة خلفية.

```bash
# 1) استنساخ المشروع
 git clone https://github.com/ABOODAlaqeel/Front-and-Risk-Management.git
 cd Front-and-Risk-Management

# 2) إعداد البيئة
cp .env.example .env

# 3) تثبيت الاعتماديات
npm ci

# 4) تشغيل وضع العرض التجريبي
npm run dev:demo
```

على Windows PowerShell استخدم `Copy-Item .env.example .env` بدل أمر `cp`. بعد التشغيل، يعرض Vite عنوان الخادم المحلي في الطرفية، وغالبًا يكون `http://localhost:5173`.

## إعداد الاتصال بالخدمة الخلفية

للتشغيل مع API فعلية، عدّل `.env` ثم شغّل وضع API:

```dotenv
VITE_API_BASE_URL=http://localhost:5000/api/v1
VITE_DEMO_MODE=false
VITE_DEBUG=false
```

```bash
npm run dev:api
```

| المتغير | الغرض |
| --- | --- |
| `VITE_API_BASE_URL` | العنوان الأساسي لخدمة API الخلفية. |
| `VITE_APP_NAME` | اسم يظهر في إعدادات التطبيق عند الحاجة. |
| `VITE_APP_ENV` | توصيف بيئة التشغيل، مثل `development` أو `production`. |
| `VITE_DEMO_MODE` | يفعّل وضع العرض التجريبي المعتمد على التخزين المحلي. |
| `VITE_DEBUG` | يفعّل سجلات تشخيصية إضافية في الواجهة. |

> لا تضع رموز وصول أو أسرارًا داخل أي متغير يبدأ بـ `VITE_`، لأن Vite يضمّن هذه القيم في تطبيق المتصفح. استخدمها فقط لقيم إعداد علنية مثل عنوان API أو أعلام الميزات.

## ملاحظات التنظيم والجودة

تحتفظ `.gitignore` بالفعل بمجلدات `dist/` و`node_modules/` وملفات البيئة خارج التتبع. ينبغي أن يبقى ملف `.env` محليًا فقط، مع اعتماد `.env.example` كمرجع آمن للإعداد. ويُستحسن أيضًا عدم رفع ملفات البناء أو السجلات أو بيانات الاختبار إلى المستودع، ما لم يكن ذلك جزءًا مقصودًا من آلية النشر.

عند إضافة وحدة جديدة، ضَع صفحة العرض في `src/pages`، وأضف مسارها وتفويضها في `src/routes/AppRoutes.tsx`، واجعل استدعاءات الخدمة في `src/api`. يحافظ هذا الفصل على وضوح التوجيه والصلاحيات والتكاملات.

## النشر

ينتج أمر البناء ملفاته في `dist/`. يتضمن المشروع إعداد `vercel.json` لإعادة توجيه المسارات إلى `index.html`، وهو مناسب لتشغيل تطبيق React أحادي الصفحة على Vercel أو أي استضافة ساكنة مكافئة تدعم إعادة كتابة المسارات.

## المساهمة

اعمل في فرع مستقل، وفحص `npm run lint` قبل فتح طلب دمج. عند تغيير نموذج بيانات أو تكامل API، حدّث الأنواع وعميل الخدمة والحالات التجريبية ذات العلاقة، ولا تضع بيانات اعتماد أو نواتج بناء ضمن التغييرات.
